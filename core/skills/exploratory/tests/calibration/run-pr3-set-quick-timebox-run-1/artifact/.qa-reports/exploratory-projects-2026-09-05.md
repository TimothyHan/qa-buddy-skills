## 상세 발견 사항

### 발견 1: 검색 결과 0건일 때 "완전히 빈 계정" 메시지를 재사용
**범주:** 결함 | **심각도:** Minor | **우선순위:** Low
**초점 영역:** AC5 검색 | **발견 경로:** 입력 변형 (일치하지 않는 검색어)
**수행한 것:** 프로젝트 2개가 있는 계정에서 검색창에 "zzznotfound" 입력
**기대한 것:** AC5는 "검색어와 일치하는 행만 표시"만 명시하지만, 검색 결과 0건과 AC6의 "계정에 프로젝트가 아예 없음"은 사용자에게 다른 의미이므로 구분된 메시지가 필요
**실제 일어난 것:** AC6 전용으로 정의된 "No projects yet" 메시지가 그대로 표시됨 — 실제로는 프로젝트가 2개 있는데 없는 것처럼 보임
**증거:** `.qa-reports/screenshots/search-no-results.png`
**콘솔/네트워크:** 정상 (에러 없음)
**조치:** `/qa-test-cases`에 AC5 신규 시나리오로 반영("검색 결과 없음 시 문구") — dev 논의 후 "일치하는 프로젝트 없음" 등으로 구분 권장

### 발견 3: 잘못된 로그인 요청이 12.5초 소요 (1회 관찰)
**범주:** 질문 | **심각도:** Minor | **우선순위:** Low
**초점 영역:** AC1 로그인 | **발견 경로:** 체감 성능
**수행한 것:** 잘못된 이메일/비밀번호로 로그인 시도
**기대한 것:** 다른 API 호출과 비슷한 응답 시간 (수백 ms)
**실제 일어난 것:** `POST /api/auth/login` 실패 응답까지 12,509ms 소요. 이후 정상 자격증명 로그인은 빠르게 응답함(재현 시도 안 함 — 세션당 1회만 관찰)
**증거:** 콘솔 로그 `console-2026-09-05T08-36-09-012Z.log` (타임스탬프 12509ms)
**콘솔/네트워크:** `401 Unauthorized`, 응답 자체는 정상이나 지연이 큼
**조치:** dev에게 재현 여부 확인 요청(질문) — 콜드 스타트/빌드 컴파일 가능성. **not reproduced under: 반복 로그인 시도** (REF-playbook/defect-lifecycle#not-reproducible 원칙상 조건 하나만 관찰했으므로 결론 보류)

**범주:** UX 개선사항 | **심각도:** Minor | **우선순위:** Low
**초점 영역:** AC5 검색 / 상태 필터(범위 외) | **발견 경로:** 접근성
**수행한 것:** 로그인 후 프로젝트 목록 페이지 접근성 스냅샷 확인

**증거:** 접근성 스냅샷 (`f2e5`, `f2e6` — role/name 누락)
**콘솔/네트워크:** 정상
**조치:** UX 개선 사항으로 백로그에 기록; `/qa-test-cases`에 접근성 케이스 추가 검토

## 확인된 정상 동작 (회귀 방지용 신규 커버리지 후보)
- 빈 이름 제출 → "Name is required" 정상 거부 (서버 400)
- 공백만 있는 이름 제출 → 동일하게 정상 거부

- 삭제 확인 다이얼로그에서 "Keep" 클릭 시 취소되어 프로젝트 유지됨

- 상태 필터(All/Active/Paused, 범위 외 기능)는 필터링 로직 자체는 정확
