# 탐색적 테스트 휴리스틱
<!-- qab: scope=exploratory tier=must -->

체계적으로 탐색하기 위한 기법입니다. `/qa-exploratory`에서 차터를 생성하고 세션을 실행할 때 사용합니다.

## 휴리스틱 범주
<!-- qab: id=heuristic-categories -->

기능 유형에 따라 관련 범주를 선택합니다:

| 범주 | 탐색 대상 |
|------|----------|
| **입력 변형** | 경계값, 빈 값, null, 특수 문자, 유니코드, 최대 길이, 음수, 0, 매우 큰 값 |
| **상태 전환** | 앞으로/뒤로 이동, 흐름 중간에 새로고침, 이탈 후 복귀, 세션 타임아웃, 동시 편집 |
| **오류 복구** | 동작 중 네트워크 장애, 잘못된 서버 응답, 부분 저장, 오류 후 실행 취소 |
| **데이터 무결성** | 저장한 데이터가 입력과 일치하는지, 반올림 문제, 잘림 문제, 인코딩 문제 |
| **교차 기능** | 이 기능이 기존 기능을 깨뜨리는지 확인합니다. feature-map.json에서 관련 기능을 확인합니다 |
| **사용자 페르소나** | 신규 사용자, 파워 유저, 관리자, 읽기 전용 사용자, 데이터가 없는 사용자, 데이터가 많은 사용자 |
| **환경** | 다양한 브라우저, 모바일 뷰포트, 느린 네트워크, JavaScript 비활성화 |
| **동시성** | 탭 2개, 동일 항목을 2명이 편집, 빠르게 반복하는 동작 |
| **접근성** | 키보드 탐색, 스크린 리더 호환성, 포커스 관리, 색상 대비 |
| **체감 성능** | 체감 속도, 로딩 인디케이터, 조작 시 반응성 |

## 휴리스틱별 기법
<!-- qab: id=techniques-per-heuristic -->

**입력 변형:** 빈 값으로 제출, 한 글자 입력, 최대 길이 + 1, 특수 문자(`< > " ' & ; -- {} [] () / \`), 유니코드(이모지, CJK, RTL, 제로 폭), 숫자(0, -1, 99999999, 0.001, NaN), 붙여넣기 vs 직접 입력, 브라우저 자동 완성.

**상태 전환:** 흐름을 절반까지 진행한 뒤 브라우저 뒤로가기/새로고침, 탭 2개로 한쪽에서 완료 후 다른 쪽 시도, 흐름 시작 후 10분 이상 대기 후 완료 시도, 링크를 통해 다른 페이지로 이동한 뒤 돌아오기.

**오류 복구:** 유효성 검증 오류 발생 후 수정하여 재제출, 다단계 흐름에서 3단계 실패 후 2단계로 돌아갈 수 있는지 확인, 개발자 도구로 네트워크 오류를 강제 발생시켜 UI가 복구되는지 확인, 잘못된 데이터 입력 후 오류 발생 -> 필드를 지우면 오류가 사라지는지 확인.

**교차 기능:** 새 기능을 사용한 후 관련 기능을 점검합니다. 새 기능의 데이터가 관련 화면에서 올바르게 표시되는지 확인합니다. 기존 기능이 정상 동작하는지 확인합니다. feature-map.json을 참고합니다.

**사용자 페르소나:** 신규 사용자(데이터 없음, 처음 사용), 파워 유저(데이터 많음), 제한된 권한, 빈 상태에서 채워진 상태로의 전환.

## 발견 항목 분류
<!-- qab: id=finding-categories -->

| 분류 | 설명 | 예시 |
|------|------|------|
| **새로운 테스트 시나리오** | 테스트 케이스가 필요한 미검증 시나리오 | "송장 금액 = 0인 경우에 대한 테스트 없음" |
| **결함** | 동작이 올바르지 않은 경우 | "중복 이메일에 대한 오류 메시지가 표시되지 않음" |
| **UX 개선 사항** | 동작은 하지만 경험이 좋지 않은 경우 | "저장 중 로딩 인디케이터가 없음" |
| **누락된 요구사항** | AC에서 다루지 않았지만 다뤄야 하는 항목 | "흐름 도중 취소할 방법이 없음" |
| **질문** | 팀 논의가 필요한 항목 | "삭제한 항목을 복구할 수 있어야 하는지?" |
