# 수동 vs 자동화 및 테스트 유형
<!-- qab: scope=test-plan,test-cases,exploratory,start -->

## 핵심 원칙
<!-- qab: id=core-principle -->

**100% 자동화를 목표로 하지 않습니다.** 이는 비현실적이며, 다른 방법으로
품질을 개선할 수 있는지 검토하는 것을 방해합니다.

## 자동화 가이드라인
<!-- qab: id=automation-guidelines -->

| 가이드라인 | 세부 사항 |
|-----------|----------|
| **기능 테스트 케이스를 자동화합니다** | 현재 기술적 역량 범위 내에서 자동화합니다 |
| **비동기 프로세스는 자동화하지 않습니다** | 불안정 테스트가 됩니다. 수동 실행 대상으로 표시합니다 |
| **자동화는 모든 계층에 걸칩니다** | Unit (개발자), API (RestAssured), E2E (Playwright) |
| **테스트를 적절한 계층에 배치합니다** | Unit이나 API 수준에서 테스트할 수 있는 것을 E2E로 자동화하지 않습니다 |

## 수동 테스트 케이스를 작성하는 경우
<!-- qab: id=manual-test-cases -->

| 유형 | 목적 | 작성 시점 | 실행 시점 |
|------|------|----------|----------|
| **자동화가 어려운 경우** | 비동기 프로세스, 기술적 제약 | 테스트 케이스 생성 시 | QA 단계 |
| **사용자 경험** | 주관적 품질 판단: 사용감이 자연스러운가? | 테스트 케이스 생성 시 | QA 단계 |
| **UAT 시나리오** | 워크플로우 중심 검증 | 기능 준비가 완료된 시점 | 릴리스 전 최종 확인 |
| **탐색적 테스트** | 스크립트 없이 새로운 시나리오를 발견 | 기능 준비가 완료된 시점 | 기능 테스트 이후, UAT 이전 |

## UAT vs 기능 테스트
<!-- qab: id=uat-vs-functional -->

| 측면 | 기능 테스트 (E2E) | UAT |
|------|-------------------|-----|
| 초점 | 원인과 결과 (입력 -> 예상 출력) | 사용자 워크플로우 완료 |
| 구조 | 구체적인 단계와 구체적인 검증 항목 | 시나리오 중심, 사용자 목표 기반 |
| 핵심 질문 | "이 기능이 올바르게 동작하는가?" | "사용자가 업무를 완료할 수 있는가?" |
| 예시 | "유효한 데이터로 폼을 제출하면 성공 메시지가 표시된다" | "신규 직원이 온보딩을 처음부터 끝까지 완료할 수 있다" |

## 탐색적 테스트
<!-- qab: id=exploratory-testing -->

탐색적 테스트는 수동 기능 테스트가 아닙니다. 탐색적 테스트는 다음과 같습니다:
- **스크립트 없음:** 사전에 정의된 단계가 없습니다. 테스터가 자유롭게 탐색합니다.
- **목적:** 알려지지 않은 사용자 시나리오를 발견하고, UX를 점검하며, 전반적인 완성도를 평가합니다.
- **결과물:** 테스트 스위트에 추가할 새 테스트 시나리오와 UI/UX 개선 제안을 도출합니다.
- **시점:** 기능 준비가 완료된 후, UAT 이전에 수행합니다.

템플릿과 실행 가이드는 `/qa-exploratory` 스킬을 참조합니다.

## 팀별 절차
<!-- qab: id=team-specific-processes -->

**테스트 데이터 관리:** `features-kb/team-practices/test-data.md` 파일이 정의되어 있으면 참조합니다. 시딩, 정리, fixture, 격리, 공유 vs 개인 테스트 데이터를 다룹니다.

**접근성 요구사항:** `features-kb/team-practices/accessibility.md` 파일이 정의되어 있으면 참조합니다. WCAG 준수 수준, 테스트 도구, 접근성 테스트가 필요한 기능을 다룹니다.
