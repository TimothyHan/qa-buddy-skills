# 테스트 지표

## 코드 커버리지

- **목표:** 코드 커버리지 약 80%.
- **절대적인 규칙이 아닙니다.** 80% 미달이 PR 머지를 차단하지 않습니다.
- **책임:** PR 작성자가 80%를 달성할 수 없었거나 현실적이지 않은 이유를 설명합니다.
- **목적:** 완벽이 아닌 규율을 장려합니다. 커버리지만으로는 품질을 보장할 수 없습니다.

## 테스트 커버리지 (요구사항 커버리지)

테스트 커버리지 = (테스트 케이스로 커버한 요구사항 및 AC) / (전체 요구사항 및 AC).

**규칙:**

- 각 요구사항/AC를 여러 테스트 케이스로 커버할 수 있습니다.
- 각 요구사항/AC를 **최소 하나의** 테스트 케이스로 커버해야 합니다.
- **100% 테스트 커버리지가 안전을 의미하지 않습니다.** 알려진 요구사항 100%에 최소 하나의 테스트가 있다는 뜻일 뿐입니다.
- **테스트 커버리지 분석은 누락된 시나리오를 찾는 데 집중합니다.** 이는 주로 탐색적 테스트를 통해 달성합니다.

## 결함 지표

### 필수

| 지표 | 산출 공식 | 목표 | 수집 방법 |
|------|----------|------|----------|
| **결함 유출률** | 운영 환경 결함 / 전체 발견 결함 | <10% | Jira 레이블 (`production-bug` vs `pre-release-bug`) 또는 KB 결함 파일. 스프린트별로 집계합니다. |
| **심각도 분포** | 스프린트별 심각도 기준 결함 분포 | Normal/Minor가 대다수. Blocker/Critical은 소수여야 합니다. | Jira 또는 KB `bugs/` 파일을 스프린트별로 확인합니다. |
| **MTTR (평균 해결 시간)** | 결함 등록부터 수정 검증까지 평균 소요 시간 | Blocker: 당일. Critical: 동일 스프린트 내. | Jira에서 `bug created`부터 `/verify-fix VERIFIED` 일자까지 측정합니다. |

### 선택

| 지표 | 산출 공식 | 도입 시점 |
|------|----------|----------|
| **DRE (결함 제거 효율)** | 릴리스 전 발견 결함 / (릴리스 전 + 릴리스 후) | 결함 유출률을 이미 추적하고 있을 때. 목표: >90%. |
| **MTTD (평균 탐지 시간)** | 코드 머지부터 결함 발견까지 평균 소요 시간 | Shift-left 성숙도를 중점적으로 개선할 때. |
| **결함 재오픈율** | Fixed에서 Open으로 재전환된 결함 비율 | 충분한 결함 건수(스프린트당 약 20건 이상)가 확보되었을 때. |
| **결함 밀도** | 에픽 또는 스토리 포인트당 결함 수 | 에픽-결함 연결이 일관되게 구축되었을 때. |

## 테스트 건전성 지표

### 필수

| 지표 | 산출 공식 | 목표 | 수집 방법 |
|------|----------|------|----------|
| **테스트 통과율** | CI 단계별 테스트 통과 비율 | 단계별(PR/develop/main) >95% | CI 파이프라인 결과. Playwright/Jest 출력을 확인합니다. |
| **불안정 테스트 비율** | 통과/실패가 일관되지 않는 테스트 비율 | <2% | Datadog 불안정 테스트 추적기, 또는 CI에서 재실행 통과 건수를 집계합니다. |
| **요구사항 커버리지 추이** | 최소 하나의 테스트 케이스가 있는 AC 비율 (스프린트별) | 증가 또는 유지. 감소하면 안 됩니다. | KB 추적성 매핑. Sprint-status에서 자동 산출합니다. |

### 선택

| 지표 | 산출 공식 | 도입 시점 |
|------|----------|----------|
| **테스트 실행 시간** | 전체 스위트 실행 시간 및 추이 | 스위트가 15분 한도에 근접할 때. |
| **자동화율** | 자동화된 테스트 케이스 / 전체 테스트 케이스 | 로드맵 계획 용도이며, 일상적 의사결정에는 사용하지 않습니다. |
| **테스트 케이스 증가 vs 기능 증가** | 스프린트당 신규 테스트 케이스 / 신규 스토리 수 | 요구사항 커버리지 추이만으로 부족할 때. |
| **테스트 유지보수 비용** | 테스트 수정 커밋 / 테스트 추가 커밋 | 팀이 유지보수 부담을 느낄 때. 정확한 측정이 어렵습니다. |
