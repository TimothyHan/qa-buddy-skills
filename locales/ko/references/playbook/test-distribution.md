# 테스트 분포 (테스트 피라미드)
<!-- qab: scope=test-plan,test-cases,review-ticket,exploratory,start -->

## 기본 목표: 테스트 피라미드
<!-- qab: id=test-pyramid -->

| 계층 | 목표 % | 프레임워크 | 담당 |
|------|--------|-----------|------|
| Unit | 60% | 프로젝트별 상이 | 개발자 |
| API / Integration | 30% | RestAssured | 개발자 + SDT |
| E2E | 10% | Playwright | SDT |

## 변형: 테스트 다이아몬드
<!-- qab: id=test-diamond -->

단위 테스트 가능한 코드가 적은 프로젝트도 있습니다 (예: 통합 중심 서비스,
복잡한 API 위의 얇은 UI). 이 경우 다이아몬드 형태를 사용할 수 있습니다:

| 계층 | 목표 % |
|------|--------|
| Unit | 20% |
| API / Integration | 70% |
| E2E | 10% |

## 중복 제거 규칙
<!-- qab: id=deduplication-rules -->

**계층 간 중복 테스트를 만들지 않습니다.**

1. 시나리오를 **단위 테스트**로 커버했다면, 동일 시나리오에 대해 별도의 API 또는
   E2E 테스트를 작성하지 않습니다.

2. 시나리오를 **API 테스트**로 커버했다면, 동일 시나리오에 대해 별도의 E2E 테스트를
   작성하지 않습니다.

3. **예외: 핵심 기능.** Blocker/Critical 심각도의 핵심 기능인 경우,
   릴리스 신뢰도를 높이기 위해 계층 간 중복을 허용합니다.

## 테스트 케이스 생성 시 적용
<!-- qab: id=test-case-generation -->

`/qa-test-cases`로 테스트 케이스를 생성할 때:
- 각 테스트 케이스를 **가장 낮은 적절한 계층**에 먼저 배정합니다.
- 하위 계층으로 충분히 테스트할 수 없을 때만 상위 계층으로 승격합니다.
- 중복이 있으면 표시하고 존재 이유를 설명합니다.
- SDT가 분포 형태를 확인할 수 있도록 결과에 분포를 표시합니다.
