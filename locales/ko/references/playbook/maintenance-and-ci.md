# 테스트 유지보수 및 CI/CD 게이트

## 테스트 소유권

**SDT가 E2E 및 API 테스트 스위트를 유지보수합니다.** 개발자가 단위 테스트를
유지보수합니다.

## 테스트 폐기

다음 경우에 테스트를 폐기합니다:
- **기능을 제거한 경우.** 해당 기능의 모든 테스트를 삭제합니다.
- **기능이 크게 변경된 경우.** 기존 테스트가 더 이상 유효하지 않으므로 수정하지 말고 새로 작성합니다.
- **테스트가 영구적으로 불안정한 경우.** 불안정 테스트 처리 절차를 모두 거친 후에도 수정할 수 없으면 제거합니다.

## 불안정 테스트(Flaky Test) 처리 절차

```
테스트가 간헐적으로 실패합니다
  |
  |-- 최대한 빨리 수정합니다 (최우선: 근본 원인 수정)
  |
  |-- 수정이 복잡한 경우:
  |     |-- 격리: 테스트를 임시로 건너뜁니다 (@skip 또는 동등한 방법)
  |     |-- 불안정 테스트 트래커에 등록합니다 (Datadog)
  |     |-- 현재 또는 다음 스프린트 내에 수정 일정을 잡습니다
  |
  |-- 합리적인 노력 후에도 수정할 수 없는 경우:
        |-- 테스트를 폐기합니다
        |-- 테스트 파일 또는 트래커에 사유를 기록합니다
        |-- 해당 시나리오에 다른 테스트 접근 방식이 필요한지 검토합니다
```

## 실행 시간 예산

- **목표:** 전체 테스트 스위트를 **15분** 이내에 완료합니다.
- 스위트가 15분을 초과하면 다음 항목을 조사합니다:
  - 병렬 처리가 가능한지
  - 최적화할 수 있는 느린 테스트가 있는지
  - 하위 계층으로 이동할 수 있는 테스트가 있는지
  - 별도 일정(야간)으로 실행할 수 있는 테스트가 있는지

## CI/CD 파이프라인 단계

세 단계 모두 **동일한 테스트 세트**를 실행합니다:

| 단계 | 트리거 | 실행 테스트 | 실패 시 |
|------|--------|-----------|---------|
| **PR** | Pull request 생성/업데이트 | Unit + API + E2E (전체 스위트) | **머지 차단** |
| **develop 머지** | PR을 develop에 머지 | Unit + API + E2E (전체 스위트) | **파이프라인 차단** |
| **main 머지** | PR을 main에 머지 | Unit + API + E2E (전체 스위트) | **파이프라인 차단** |

## 실패 정책

- **테스트가 실패하면 파이프라인을 차단합니다.** 예외는 없습니다.
- **테스트가 한 번이라도 실패하면 반드시 조사합니다.** 재실행에서 통과하더라도 마찬가지입니다.

## 불안정 테스트 추적

- 불안정 테스트는 **Datadog**(별도 트래커)에서 추적합니다.
- CI에서 간헐적으로 실패하는 테스트는 Datadog 불안정 테스트 트래커에 추가합니다.
- 해결 방법은 위의 불안정 테스트 처리 절차를 따릅니다.

## 브라우저 매트릭스

Playwright 테스트는 다음 브라우저에서 실행합니다:
- **Chrome, Firefox, Safari, Edge** (기본적으로 4개 모두 대상).
- 브라우저별 제한 사항은 테스트 파일에 코멘트로 기록합니다.
