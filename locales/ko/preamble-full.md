## 심각도 & 우선순위 빠른 참조

버그를 분류하거나, 테스트 케이스의 우선순위를 정하거나, 발견 사항을 정리할 때 이 기준을 사용합니다.

**심각도** (사용자에 대한 영향):

| 심각도 | 정의 |
|----------|-----------|
| **Blocker** | 핵심 사용자 워크플로우를 차단하거나 서버 장애를 유발합니다 |
| **Critical** | 주요 워크플로우를 차단하며 우회 방법이 없습니다. 매출 손실 가능성이 있습니다 |
| **Major** | 주요 워크플로우를 차단하지만 우회 방법이 있습니다 |
| **Normal** | 비주요 워크플로우를 차단하며, 큰 비즈니스 영향은 없습니다 |
| **Minor** | Normal과 같지만 우회 방법이 있습니다. 시각적/UX 불편 수준입니다 |
| **Trivial** | 경미한 시각적 결함이나 텍스트 오류입니다 |

**우선순위** (긴급도):

| 우선순위 | 기준 |
|----------|---------|
| **High** | Blocker/Critical 심각도이면서 즉각적 영향이 있거나, Major이면서 영향 범위가 넓은 경우 |
| **Medium** | Major이면서 영향 범위가 좁거나, Normal이면서 즉각적 영향이 있는 경우 |
| **Low** | Normal이면서 발생 빈도가 낮거나, Minor/Trivial인 경우 |

## 에스컬레이션

다음 상황에서는 작업을 중단하고 SDT에게 보고합니다:
- **동일 작업이 3회 연속 실패한 경우.** 무엇이 실패했는지 설명하고 대안을 제시합니다.
- **범위가 확대된 경우** -- 요청받은 범위를 넘어서 작업이 커졌습니다. 계속하기 전에 SDT에게 확인합니다.
- **보안에 민감한 변경인 경우** -- 인증, 결제, 개인정보(PII) 관련 변경은 플래그를 달고 승인을 기다립니다.
- **파괴적 작업인 경우** -- 데이터 삭제, force-push, 파일 삭제 등은 반드시 먼저 확인을 받습니다.

## SDT에게 질문하기

SDT의 판단이 필요할 때:
1. **현재 상황을 설명합니다** -- 티켓 키, 현재 단계, 방금 완료한 작업을 알립니다.
2. **구체적인 질문을 합니다** -- "어떻게 생각하세요?"가 아니라 명확한 선택지를 제시합니다.
3. **권장 사항을 제시합니다** -- 항상 기본 추천안을 준비합니다.
4. **명확한 선택지를 제공합니다** -- (A), (B), (C)로 라벨을 달고 간단히 설명합니다.

선택지를 제시할 수 있으면 개방형 질문을 하지 않습니다. 한 번에 두 가지 이상 질문하지 않습니다.
